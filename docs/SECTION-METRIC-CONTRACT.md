# Общие правила показателей

План-факт получает определения воронок из `ReportsService.getTeamFunnelDefinition`.
Отдельные списки этапов и формулы выборки сделок в план-факте не поддерживаются.

- Лиды Sales: сделки в воронке продаж, созданные за период, с текущим значением «Маркетинг = Принято». Автосделки сборки и партнёры сюда не входят.
- КП, счета и оплаты: первый вход сделки в соответствующий набор этапов за всю историю. В результат попадает дата этого входа. Повторное движение карточки не создаёт новую оплату.
- Ответственный: текущий. Передача Sales-сделки сотруднику другого отдела не убирает её из результата воронки продаж.
- CSM: воронки «База» и «Закрепленные компании», текущие ответственные CSM. КП — «Сделано предложение», не «КП подготовлено».
- Число оплат и сумма оплат используют один набор сделок. Сумма берётся из текущего значения сделки.
- Отгрузки: уникальные сделки сборки с переходом в этап отгрузки за период. Расчёт общий для план-факта и фактической части прогноза. CSM и остальные ответственные образуют непересекающиеся группы.
- За текущий месяц план-факт и прогноз используют один сохранённый результат отгрузок. Дневные отгрузки выделяются из него по дате первого входа в этом месяце.
- Предустановленные дни, недели и месяцы считаются по Москве, независимо от часового пояса компьютера.
- Конверсия: отношение двух показателей за выбранный период. Это не вероятность перехода одной когорты; результат может превышать 100%.
- В план-факте Sales «КП» означает презентованные КП. Поэтому «лиды → КП» нельзя сравнивать с колонкой отчёта «лиды → КП подготовлено».
- Прогноз содержит фактическую отгрузку и оценку будущей. Он не обязан совпадать с оплатами. РОП и SLA показывают текущую нагрузку, а не месячные достижения.
- Нет активности — ноль. Неопределимая конверсия или недоступное значение — `null`, не ноль.

Встроенные отчёты используют серверные определения даже при запросе из старой вкладки.
Пользовательские отчёты с явным режимом событий сохраняют собственную семантику: каждое действие и его исполнитель.

После изменения правил обновляется версия метрик. Выкладка прогревает отчёты и запускает
`scripts/verify-section-consistency.cjs`: сверку по менеджерам, итогам, дням и месяцам,
отгрузкам и фактической части прогноза. Эта проверка не заменяет сверку исходных данных с amoCRM.
