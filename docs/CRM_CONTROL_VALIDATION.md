# Проверка реализации «Контроль CRM»

18.09.2026. Проверен код в рабочей копии; на рабочий сервер он не выкладывался. Настоящие данные CRM не изменялись.

## Результат

- `npm test`: 23 набора, 189 тестов прошли, включая полный справочник типов задач amoCRM.
- `npm run typecheck`: API и Web прошли.
- `npm run frontend:gate`: проверка оформления и типы Web прошли.
- `npm run build`: API и Web собраны.
- `git diff --check`: ошибок пробелов нет.

В новых тестах проверяются границы дат, полнота источников, правила отделов, история эпизодов, роль пользователя из базы, доступ к доказательствам, блокировки запуска, потеря блокировки, решения руководителя, фильтрация, повторные попытки скриншотов и смена владельца во время съёмки.

Справочник типов задач читается через `GET /account?with=task_types`; типы без существующих задач также доступны. Проверены отказ источника и несовпадение аккаунта: в этих случаях неполный локальный список не подставляется.

## Подготовка выкладки

В `scripts/deploy-production-release.sh` добавлен откат при ошибке запуска служб. Ошибки переключения ссылки останавливают откат до перезапуска. Очистка старых релизов сохраняет текущий и предыдущий релиз независимо от времени изменения каталога. Локальная проверка с подменёнными системными командами прошла: успешный откат, ошибки `ln`, `mv`, перезапуска, отсутствие предыдущего релиза и очистка при `KEEP_RELEASES=1`. Синтаксис Bash проверен; сценарий — `.codex-run/crm-control/deploy-rollback-qa.sh`.

## Зависимости перед выкладкой

Fastify обновлён с 5.11.3 до 5.12.1 через `overrides.fastify`; версия Nest сохранена. Текущий `@nestjs/platform-fastify@11.2.3` также объявлен в корневых зависимостях: это позволяет npm 11.8.0 корректно применить override к зависимости workspace. Объявления используют один установленный адаптер, существующий override `fast-uri` сохранён. При обновлении адаптера нужно пересмотреть эту фиксацию.

В отдельной копии manifest и lockfile прошла чистая установка `npm ci --ignore-scripts`. В рабочей копии после установки `npm ls fastify @nestjs/platform-fastify` завершился без ошибок: адаптер 11.2.3, Fastify 5.12.1 с применённым override. `npm audit --omit=dev` завершился с кодом 0: уязвимостей нет. Повторно прошли типы API и все 189 тестов.

## Проверка базы и сервиса

Для изолированной проверки использован PGlite 0.5.8 с PostgreSQL-протоколом через pglite-socket 0.2.11. Временные зависимости находятся в игнорируемой папке `.codex-run/crm-control`, в продукт они не добавлены. Это не проверка рабочего PostgreSQL 16 под нагрузкой: Docker Desktop на этой машине не запустился.

Из схемы до изменения создана отдельная база, затем применён SQL миграции `0024_crm_control`. Сравнение полученной базы с новой Prisma-схемой вернуло `No difference detected`.

Через настоящий Prisma-клиент и `CrmControlService`, с явно тестовым источником amoCRM, прошли семь сценариев:

1. Сохранение настроек и ограничение изменений владельцем.
2. Очередь проверки, запись результатов, повтор с тем же ключом, область менеджера и РОПа.
3. Неизменность исходных данных после решения и отказ в чтении чужого подтверждения.
4. Подтверждение `REVIEW`, фильтр `FAIL`, последующее исключение с причиной и сроком.
5. Исправление, сохранение прежнего факта и новый эпизод при повторе нарушения.
6. Закрытие сделки и завершение прежних случаев без удаления истории.
7. Защита связанной истории ограничениями внешних ключей.

Подготовка: `.codex-run/crm-control/pglite-server.mjs`; сценарии: `.codex-run/crm-control/integration.cjs`. Это локальные вспомогательные файлы, не часть поставки.

## Проверка интерфейса

В Chrome проверены ширины 320, 390, 768 и 1440 px. API подменялся отдельными тестовыми ответами только внутри браузерного теста, в коде приложения фиктивных данных нет.

Проверены сводка, фильтр отдела, поиск, длинные имена, карточка результата, обязательная причина решения и срок исключения, каталог правил, поиск по 80 этапам, закрытие списка через Escape, сохранение ID настроек, пустые данные и отказ 403. Снимки запрашиваются с Bearer-токеном. Повторный сбор переводит ошибку в ожидание. На мобильном экране таблица прокручивается по горизонтали, шапка новой вкладки уходит вверх при прокрутке. Другие вкладки сохраняют прежнее поведение. Ошибок JavaScript в прогоне нет.

Снимки браузерного теста: `tmp/crm-control-ui/desktop.png`, `mobile.png`, `mobile-detail-viewport.png`. Изображение доказательства в тесте — нейтральный тестовый PNG, а не реальная карточка клиента.

Дополнительно проверен ввод сроков в минутах, часах и днях: 20 минут сохраняются как `20/60` часа, смена единицы не меняет длительность, ноль не проходит форму. Повторно прошли `frontend:gate`, сборка Web и браузерная проверка, включая экран 390 px. Снимки: `tmp/crm-control-ui/duration-desktop.png`, `duration-mobile-viewport.png`.

## Что ещё нужно проверить при подключении

- Рабочий PostgreSQL, развёртывание API/Web/worker, каталог пользователей и реальные настройки этапов.
- Реальная браузерная сессия сборщика, файловые права и общая папка доказательств.
- Сквозная проверка реального PNG через очередь, включая завершение сессии amoCRM.
- Фактическая продолжительность полного обхода и скорость сбора PNG на объёме рабочего аккаунта.

Селекторы сборщика сверены с настоящей карточкой amoCRM в режиме чтения. Автоматическое сохранение PNG с реальной сессией не запускалось. До подключения сессии интерфейс показывает отсутствие скриншота явно. Ограничения автоматической проверки оффера, файлов и содержания коммуникаций перечислены в [инструкции запуска](CRM_CONTROL_OPERATIONS.md).
