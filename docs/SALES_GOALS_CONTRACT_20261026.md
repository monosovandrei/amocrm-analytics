# Цели менеджеров продаж: согласованное определение

Подтверждено владельцем 26 октября 2026 в этом чате. Это требования к изменению, не подтверждение выкладки или записи планов в базу.

## Две месячные цели

- Маржа отгрузок в EUR: 40 000 для Эда Айвазяна и Мерада Билала; 30 000 для остальных десяти действующих менеджеров продаж. Имена сверены с группой Sales в CRM. При настройке нужны внутренние связи с CRM-сотрудником, не сравнение имени в рабочем расчёте.
- Продажи: 14 уникальных оплаченных сделок на каждого менеджера. Месяц определяется оплатой, дата отгрузки не влияет. Повторный перевод той же сделки в оплаченный этап не создаёт новую продажу. Перевод в оплаченный этап CRM не равнозначен сверке с банковским реестром.
- КП и счета остаются показателями активности, не дополнительными обязательными целями. Два целевых результата нельзя объединять в произвольный общий балл.
- Отгрузки относятся к подтверждённому коммерческому менеджеру, не к ответственному логисту. Сумма отгрузки не равнозначна её марже.
- Планы CS этой правкой не переопределяются. Уровни новых сотрудников и исторические планы не назначаются задним числом по догадке.

## Источник маржи подтверждён: Ривиле

Текущий KPI `shipments` суммирует `fact_deal_current.amount` — это сумма отгрузок, не маржа. Прогноз использует оценку 32% выручки; её нельзя объявлять фактической маржой без решения владельца.

Проверка источника 26 октября:

- Живой API amoCRM `/leads/custom_fields` вернул 96 полей сделки, в том числе новое числовое поле `815417`, «Маржа заложенная». Валюта поля не задана; единица измерения и пригодность для фактической маржи не установлены.
- В локальном справочнике `CustomFieldDefinition` этого поля пока нет, хотя некоторые значения уже есть в `fact_deal_current.custom_fields`.
- В зеркале поле присутствует у 42 из 51 866 сделок. В октябрьском пуле уникальных сборок с переходом в отгрузку — у 5 из 117. Это наличие поля, не подтверждение заполненности или достоверности значения; не показатель отдельно одного отдела по коммерческому владельцу.
- Прямая проверка API обеих предоставленных владельцем сделок, `41470057` и `41490929`, не нашла заполненного поля маржи. У каждой сумма 705 EUR.

После этой проверки владелец подтвердил: фактическая маржа отгрузок берётся из Ривиле. Поле amoCRM и оценка 32% для выполнения плана не используются.

Рабочее подключение найдено в проекте «Склад», на сервере `/deploy/home/warehouse`. Доступ проверен живым запросом чтения. Ключ не хранится в исходниках и не передаётся браузеру.

Контракт существующего отчёта «Склад»: проведённые документы (`I06_PERKELTA=2`), операции продажи 51 и возврата 52, дата документа `I06_DOK_DATA`; строки оборудования, без услуг, с прежним исключением для кода доставки `9990006`. Маржа — `I07_SUMA` минус `I07_SAVIKAINA`, базовые суммы EUR без НДС. Возврат уменьшает выручку, себестоимость и маржу. Это не прогноз.

## Реализация и ограничения выпуска

- Синхронизация выполняется в фоне: текущий месяц каждые пять минут, предыдущий каждый час, другие месяцы по запросу РОПа/администратора. На открытии страницы запросов в Ривиле нет.
- Хранятся нормализованные документы без клиентов и товарных строк; замена месячного снимка атомарна. Перед публикацией требуются два одинаковых чтения источника. Ошибка, неполная пагинация, потеря себестоимости или изменяющийся источник сохраняют предыдущий успешный снимок, но не подтверждают актуальность.
- Неизвестные коды менеджеров не назначаются по похожим именам. Администратор подтверждает код, сотрудника и отдел в «Настройки → Ривиле». Отдельно можно явно отнести код вне продаж и CS.
- Маржа имеет отдельный показатель `shipmentMargin`, не переименованный `shipments`. Последний остаётся суммой сборок amoCRM, только справочно. Старый API денежных планов сохраняется для совместимости и сверки; интерфейс плана продаж использует только две новые цели.
- Домашний экран, план-факт и TV используют один сервис расчёта и один набор сохранённых целей. КП, счета и сумма сборок на TV ранжируются по факту, без выдуманных планов.
- Первичная настройка выполняется один раз с журналом изменений. Шаблоны будущих месячных целей хранятся отдельно; существующие планы и ручные изменения не перезаписываются.
- Код 102 (Andrey Lebedev) владелец явно подтвердил как «вне продаж и CS». Его документы сохраняются в снимке Ривиле, но не входят в показатели и планы этих отделов. Связь с сотрудником amoCRM не выдумывается; решение записывается в журнал первичной настройки.
- На стенде независимо пересчитаны все 100 документов октябрьского снимка через живой API и десятичную арифметику: расхождений в выручке, себестоимости и марже нет. Это проверка на момент чтения, не обещание неизменности учётных документов.
